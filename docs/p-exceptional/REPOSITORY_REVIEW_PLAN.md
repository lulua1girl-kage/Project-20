# GitHub Repository Review Plan

## Rubric (0–5)
- Product fit: tasks, projects, habits, calendar, focus, planning
- Platform fit: Kotlin/Compose or adaptable architecture
- Offline persistence and sync design
- Modularity, documentation, code quality
- Tests and CI
- Security hygiene: secrets, authz, dependencies, releases
- Maintenance and recent meaningful activity
- License compatibility and attribution
- Accessibility/localization
- Operational complexity and self-hosted/free path

## Search groups
1. Android/Kotlin task apps
2. Offline-first todo and sync engines
3. Habit trackers and routine apps
4. Self-hosted task/project managers
5. Calendar/planner/focus apps
6. Notification scheduling examples
7. Certificate/PDF generation and verification
8. Privacy-preserving analytics/admin dashboards
9. Authentication and role-based backend examples
10. Compose/KMP cross-platform samples

## Reuse rule
Treat repositories as references, not an unreviewed code dump. Before adopting code, inspect license, maintenance, dependencies, architecture, security, and attribution requirements.

## Status
Rubric and search groups are defined. A curated 100-repository inventory and in-depth review are still pending; this document does not claim 100 repositories have been inspected.
